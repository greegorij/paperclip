# T-202607-008 — Paperclip self context rejects a human issue identifier

| Field | Value |
|-------|-------|
| ID | T-202607-008 |
| Date | 2026-07-30 |
| Status | RESOLVED LOCALLY — production pilot pending |
| Priority | P0 |
| App | Paperclip tool gateway |
| Area | `paperclip-self:get_issue_context` |
| Avoidable? | TAK — the tool contract does not distinguish UUID from the visible issue identifier |

## Evidence

The isolated OpenAI-first production pilot on `fork-v0.2.14` completed its
Codex run successfully, read the Jarvis Boot Manifest through the managed vault
gateway, produced a 229,983-byte log without a harness crash, and did not retry
the failed task action.

The functional delegation stopped before creating the Badacz child issue:

- the model called `paperclip-self:get_issue_context` with the visible
  identifier `GG-850`;
- the tool schema only says `issueId: string` and does not require or describe
  the internal UUID;
- the implementation compares the unvalidated string directly with the UUID
  database column, causing a database error and HTTP 500;
- the anti-loop instruction then correctly prevented a retry.

All 29 agents were paused after the pilot, live runs returned to zero, eleven
quarantined assignments and both temporary daily caps were restored.

## Root cause

The public tool contract and its database lookup disagree. A normal
human-facing Paperclip identifier satisfies the declared string schema but is
not accepted by the implementation. Invalid UUID input leaks through as a
database error instead of being resolved safely or rejected as a client error.

## Acceptance

- `get_issue_context` accepts either the internal issue UUID or the visible
  case-insensitive identifier within the authenticated company.
- Omitted `issueId` continues to use the issue-scoped session ID.
- A reference from another company returns not found and does not leak data.
- A malformed or unknown reference never reaches the UUID comparison as an
  invalid UUID and never returns HTTP 500.
- The tool description and parameter schema state the accepted reference forms
  and recommend omission in an issue-scoped session.
- Regression tests cover UUID, visible identifier, omitted session fallback,
  unknown reference, and cross-company isolation.
- No write-tool behavior, approval flow, or unrelated gateway contract changes.

## Production verification

Pending one fresh, isolated Jarvis → Badacz pilot after the fix is reviewed,
released, and deployed. The next pilot must not be repeated automatically by
the operator if it fails.

## Implementation and local verification

- The tool contract now states that `issueId` accepts an internal UUID or the
  visible case-insensitive identifier and recommends omission in an
  issue-scoped session.
- The lookup selects the UUID column only after matching the existing UUID
  pattern; all other references use the company-scoped identifier column.
- Unknown and cross-company references retain the existing not-found response.

Root verification:

- focused regressions: 5/5 pass;
- complete tool-gateway service test file: 21/21 pass;
- server typecheck: pass;
- diff whitespace check: pass.

The only correction pass changed three success-test assertions to read the
existing `executeTool` result envelope. Production logic was unchanged by the
correction.
