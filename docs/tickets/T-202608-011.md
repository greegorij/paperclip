# T-202608-011 — Server database credentials leak into agent processes and run artifacts

| Field | Value |
|-------|-------|

| Date | 2026-08-13 |

| Avoidable? | Yes — child process environments were built by copying the complete server environment |

## Symptom

A historical Reflection Coach run printed its environment while diagnosing missing tools. The captured artifact contained the live PostgreSQL connection credential. The value must not be copied, quoted, or committed.

The production service environment also contains non-Paperclip-prefixed provider and infrastructure credentials. Because the current inherited-environment filter only handles the Paperclip namespace, the exposure class is wider than the database credential and affects every local adapter using the shared child-process runner.

## Proven cause

Local adapter execution paths merge `process.env` into the child environment. Paperclip strips stale runtime-owned `PAPERCLIP_*` variables, but does not define a server-to-agent trust boundary for unrelated server-only settings such as database, migration, encryption, signing, backup, mail, or infrastructure credentials.

Log shaping redacts values by sensitive variable name, but a database connection URL can also appear in free text and child stdout. Logging protection is therefore not a substitute for preventing the secret from entering the child process.

## Required repair

- Build inherited agent environments through one shared policy, not adapter-local copies of `process.env`.
- Use an explicit allowlist of operating-system and CLI-auth variables required by local runtimes, then overlay resolved project/agent/routine env and Paperclip run-scoped values.
- Treat all server-only database, migration, encryption, signing, backup and infrastructure variables as non-exportable.
- Apply the same boundary to Claude, Codex and the other local process adapters so a future fleet switch cannot reopen the leak.
- Preserve adapter/project/routine env that Paperclip resolved explicitly for the run; the restriction applies to implicit inheritance from the server process, not to declared agent configuration.
- Redact credential-bearing connection strings from invocation metadata, errors and captured output as defense in depth.
- Add tests proving forbidden values never reach spawned environments or new run artifacts while required CLI auth still works.
- After deployment, rotate the PostgreSQL credential, update only legitimate server consumers, restart safely with zero active runs, and verify backups and health.
- Inventory the contaminated historical artifact and sanitize it through an auditable, backup-backed procedure without reproducing the old value.

## Completion evidence required

- Adapter matrix proves server-only secrets are absent from child processes.
- Redaction tests cover PostgreSQL-style connection strings in structured env and free text.
- Repository and generated artifacts contain no credential values.
- Production credential rotation succeeds and old credentials no longer authenticate.
- Service health, database access and backup freshness remain green.

Pre-change production baseline: the service is healthy and aligned with the private `production` branch; 24 hourly database backups exist from the preceding 24 hours and the latest observed backup completed successfully. The deployed tree contains one pre-existing untracked UI build directory, which must be classified during deployment rather than silently deleted.

Fleet configuration audit: Claude agents declare only their profile directory, Codex agents declare no env, and the three OpenCode agents explicitly declare their profile directory and OpenRouter credential. Those explicit overlays must continue to work. Database, Google, Jarvis gateway and Thulium server credentials are not declared by agents and must not be inherited implicitly.

## Prevention

The server-to-agent environment policy and secret canaries become release regression gates for every local adapter.

## Implemented repair

The shared process boundary now inherits only operating-system/runtime keys.
Provider keys and `SSH_AUTH_SOCK` are not implicit capabilities. Explicitly
resolved adapter `env` remains an unconditional overlay, including the current
OpenCode `OPENROUTER_API_KEY` configuration. All built-in local execution and
probe paths, ACP, remote execution scripts, and Claude/Codex quota probes use
the same boundary. PostgreSQL connection URIs are redacted from structured
metadata and free text as a second layer; prevention remains authoritative.
