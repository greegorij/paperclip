## Symptom

Production fleet validation can fail with `runtime-policy-max-concurrent-mismatch` for `recenzent` even when live runtime policy is correct.

Observed behavior:

- `GET /api/agents/:id` for `recenzent` returns `runtimeConfig.heartbeat.maxConcurrentRuns = 1`.
- Fleet live snapshot records `maxConcurrentRuns = null` for the same agent.
- `validate` compares desired runtime policy (`1`) with snapshot (`null`) and fails.

## Reproduction

1. Run live snapshot from `ops/fleet/jarvis/bin/fleet-config.mjs snapshot ...`.
2. Use a live API where `/api/companies/:companyId/agents` omits `runtimeConfig` and can expose `maxConcurrentRuns` as null/absent.
3. Run `validate` against that snapshot.
4. `validate` raises `runtime-policy-max-concurrent-mismatch` for `recenzent`.

## Proven root cause

Two defects in the snapshot path:

1. Snapshot source used the compact list endpoint (`GET /api/companies/:companyId/agents`) as the effective config source for each agent, without fetching full per-agent records.
2. `normalizeLiveSnapshot` did not map `runtimeConfig.heartbeat.maxConcurrentRuns` into the top-level `maxConcurrentRuns` field consumed by validator policy checks.

Result: runtime policy is present in live detail API, but lost in normalized snapshot.

## Repair plan

1. In live snapshot flow, after confirming list count is exactly 29, fetch full `GET /api/agents/:id` for each listed agent (fail-closed on any detail error, with agent label/id and HTTP status in error text).
2. Build normalized agents from full detail records, preserving required list metadata safely.
3. In `normalizeLiveSnapshot`, set:
   - `maxConcurrentRuns = runtimeConfig.heartbeat.maxConcurrentRuns ?? existingTopLevel ?? null`
   - keep `0` as `0` (no falsy coercion to null).
4. Add live-path regression tests with mocked fetch:
   - compact list lacks `runtimeConfig`,
   - recenzent detail has `runtimeConfig.heartbeat.maxConcurrentRuns = 1`,
   - snapshot output keeps `maxConcurrentRuns = 1`,
   - validate no longer reports mismatch,
   - detail GET error aborts snapshot (fail-closed).
5. Update `ops/fleet/jarvis/README.md` with full-record fetch and maxConcurrent mapping behavior.

## Resolution

- Wdrożono pełny pobór live przez listę 29 agentów + per-agent `GET /api/agents/:id` jako źródło prawdy dla runtime config.
- Wdrożono mapowanie `runtimeConfig.heartbeat.maxConcurrentRuns` do pola snapshotu używanego przez walidację polityk.
- Na produkcji przeszły kolejno: `snapshot`, `validate`, `diff`, `verify`.
- Potwierdzono brak aktywnych runów podczas wdrożenia polityk.
- Dodano test kontraktowy list-vs-detail, który blokuje regresję typu „lista nie niesie pełnego runtimeConfig”.
