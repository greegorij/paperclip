## Evidence

After `fork-v0.2.15` fixed visible-identifier resolution for
`paperclip-self:get_issue_context` (T-202607-008), a reused OpenAI-first
Jarvis pilot still failed to create the Badacz child issue.

The generated Codex boss artifact (`AGENTS-CODEX.md`) still contained the
Claude-era section **PAPERCLIP — NARZĘDZIA, NIE CURL**:

- claimed 41 `mcp__paperclip__*` write tools;
- banned shell/`curl`/`wget` for Paperclip API calls;
- told the model to use MCP write tools that Codex does not have.

Actual Codex runtime exposes only two read-only `paperclip-self` helpers
(`list_my_issues`, `get_issue_context`). Task mutations, delegation, comments,
and status changes require the canonical synced `paperclip` skill plus the
run-scoped `PAPERCLIP_API_URL` / `PAPERCLIP_API_KEY` bridge and
`X-Paperclip-Run-Id`.

## Root cause

`generateCodexJarvisInstructions` adapted vault access for the read-only Codex
boss profile but left the Paperclip control-plane section intact. The false
41-tool / blanket curl-ban contract therefore shipped into the committed
Codex instructions bundle and steered the model away from the only valid
mutation path.
