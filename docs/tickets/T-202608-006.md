# T-202608-006: Instrukcje każą agentowi nazwać cudzego ownera w unblockDescriptor

## Objaw

Instrukcje dla agentów (skill / shared prompt) sugerowały nazwanie innego
agenta jako `unblockDescriptor.owner` przy przekazaniu pracy. Serwer celowo
odrzuca agent-authored owner innego agenta / użytkownika / `"board"` z `403`
(`Agents may only name themselves as an unblock owner`).

W żywym pilocie Konfigurator dwukrotnie dostał ten `403` na PATCH `blocked`,
zostawił kartę w `in_progress` bez żywej ścieżki kontynuacji, a recovery po
udanym przebiegu natychmiast uruchomił trzeci run — aż operator go wstrzymał.

## Reprodukcja

1. Agent ma kartę `in_progress` i chce przekazać następny krok innemu agentowi.
2. Zgodnie ze starymi instrukcjami: `PATCH` → `status: "blocked"` +
   `unblockDescriptor.owner: { "agentId": "<inny-agent>" }` (lub user/`board`).
3. Route: `403` — agent nie może nazwać cudzego ownera.
4. Agent nie ustawia follow-up / `blockedByIssueIds` ani `in_review` z
   interaction; karta zostaje `in_progress` bez continuation.
5. Po finalize udanego runu recovery startuje kolejny przebieg tej samej karty.

Bez surowych ID runów — wzorzec: dwa zablokowane PATCH, osierocone
`in_progress`, trzeci run z recovery do pauzy operatora.

## Przyczyna źródłowa

1. **Mismatch instrukcja ↔ auth.** Dokumentacja / prompt uczyły ścieżki
   „nazwij ownera odblokowania”, w tym innego agenta, podczas gdy walidacja
   ownership w route celowo ogranicza agent-authored `unblockDescriptor` do
   siebie. Próby z cudzym ownerem kończą się `403` i nie powinny być
   ponawiane z innym zabronionym ownerem.

2. **Brak depth-safe handoff.** Gdy follow-up (dziecko przypisane drugiemu
   agentowi + `blockedByIssueIds`) nie da się utworzyć przez depth/permissions,
   brakowało kanonicznej ścieżki: jedna widoczna interaction
   (`suggest_tasks` / `ask_user_questions`) + `in_review`, a na końcu
   self-owned `blocked` z konkretną prośbą routingu do boardu — zamiast
   zostawiać `in_progress` bez continuation albo retry foreign-owner.

## Naprawa (lokalnie w repo, bez deployu)

Aktualne, niecommitowane poprawki docs / shared prompt (zachować; nie
commitować w ramach samego biletu):

1. **Follow-up + blocker:** gdy inny agent ma następny krok — utwórz jedną
   follow-up issue z `assigneeAgentId`, wejdź w `blocked` z
   `blockedByIssueIds`; **nie** wstawiaj tego agenta do
   `unblockDescriptor.owner`.
2. **Depth/permission fallback:** dokładnie jedna interaction
   (`suggest_tasks` lub `ask_user_questions`) z `continuationPolicy:
   wake_assignee` i źródło w `in_review` póki interaction jest pending;
   permission-only może polegać na default parent źródła; depth wymaga
   jawnego `parentId` / `defaultParentId` na najbliższego dozwolonego
   przodka (sibling), bez source-as-default-parent.
3. **Ostatni fallback:** self-owned `unblockDescriptor` + konkretna akcja
   routingu dla boardu.
4. **Zakazy:** zero retry foreign-owner; zero osieroconego `in_progress`
   po nieudanym blocked.
