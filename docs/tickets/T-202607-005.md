## Evidence

1. **Managed MCP Authorization ignored by Codex.** Paperclip wrote
   `headers = { Authorization = "Bearer …" }` into staged `config.toml`
   (mode `0600`). Current Codex config accepts `bearer_token_env_var`,
   `http_headers`, and `env_http_headers` — not the legacy `headers` key — so
   governed gateway calls ran without the bearer.

2. **Overlapping unmanaged MCP servers remained reachable.** When a seeded
   home already had `[mcp_servers.<name>]` matching a Paperclip gateway,
   Paperclip left the direct entry and added `paperclip-<name>`. The pilot
   agent could still use the unmanaged bypass under the canonical name.

3. **AGENTS-CODEX told the read-only Codex boss to open/write the vault on
   disk.** Generated boot told the agent to read
   `${JARVIS_VAULT_ROOT}/01 - Jarvis/Jarvis — Boot Manifest.md` and write via
   `apply_patch`, but that vault path is intentionally not mounted in the
   Codex boss sandbox.

## Root cause

1. Managed MCP writer used an obsolete TOML field name relative to current
   Codex.
2. Overlap policy preferred rename-and-warn over suppress-and-govern.
3. Codex instruction generator did a mechanical Claude→Codex tool rename
   (`Write/Edit` → `apply_patch`) without adapting vault access to the
   read-only MCP-only mount profile.

## Acceptance

- Managed MCP entries emit `http_headers` with `Authorization = "Bearer …"`.
- Overlapping unmanaged `[mcp_servers.<name>]` tables (and nested subtables)
  are removed; only the Paperclip-governed entry remains under the canonical
  name. Unrelated unmanaged servers survive. Stale managed blocks still
  replace cleanly. Config stays mode `0600`.
- Generated `AGENTS-CODEX.md` boots via `vault_read` + logical path
  `01 - Jarvis/Jarvis — Boot Manifest.md`, states direct vault FS/writes are
  unavailable, and requires delegation/escalation for durable vault mutations.
- Generator fails closed if legacy direct-path or direct-write claims remain.
- Committed `AGENTS-CODEX.md` regenerated from the existing fixture/source
  workflow (no new source of truth).

## Production verification (2026-07-30)

The tagged release was deployed from a clean tree with all 29 agents paused
and zero active runs. In the isolated Jarvis pilot:

- the staged Codex home reported all four overlapping direct MCP entries as
  suppressed in favor of governed gateways;
- the managed `jarvis-vault` gateway successfully returned the Boot Manifest;
- the live `AGENTS-CODEX.md` matched the committed generated artifact exactly.

The later pilot failure was a separate stdout backpressure defect tracked in
T-202607-007, after the managed MCP read had completed successfully.

## Prevention classification

- **Contract drift** — adapter emitted a field Codex no longer reads; lock
  with a regression that asserts `http_headers` and rejects bare `headers`.
- **Policy softness** — overlap must suppress unmanaged peers for governed
  names, not only warn.
- **Profile-blind translation** — Codex-specific mount/MCP constraints must
  be applied after harness translation, with fail-closed leftover scans.

## Out of scope

Periodic assignment recovery and pilot assignment quarantine (later harness/UI
slice). Recovery behaved as designed and is not changed here.
